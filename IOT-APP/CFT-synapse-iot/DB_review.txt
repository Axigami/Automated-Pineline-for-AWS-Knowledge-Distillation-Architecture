src/modules/dashboard/view/components/DashboardOverview.tsx
============================================================
UI sections in this file (mock variables): KPIS, ALERTS, ATTACK_DIST, NODES, FORENSIC_FLOWS, F1_HISTORY

1) KPI cards
- Total Devices / Online%:
  - Use: edge_nodes
    - Count: edge_nodes.id
    - Online: edge_nodes.status (e.g. 'online') OR last_seen_at freshness
- Active Alerts:
  - Use: alerts_all
    - Count: alerts_all.alert_id WHERE alerts_all.alert_status IN ('pending','verifying','confirmed')
- Cloud AI Status / flows per min:
  - Use: network_flows_feedback_all (or flow_inference)
    - Rate: count(network_flows_feedback_all.flow_id) grouped by minute on network_flows_feedback_all.flow_ts
- Data Drift Level:
  - Use: homes.data_drift_alert_level (threshold) + your computed drift metric (not stored in DBML yet)
- Security Score:
  - Typically computed; not stored in DBML (derive from alerts + SLA + drift)

2) Live Alert Feed list (ALERTS mock)
- UI fields: id, time, threat, confidence, source
  - Primary: alerts_all
    - id           -> alerts_all.alert_id
    - time         -> alerts_all.alert_first_seen_at (format to HH:mm:ss)
    - threat       -> alerts_all.alert_threat_type
    - confidence   -> alerts_all.alert_confidence
    - source text  -> alerts_all.alert_source_text
  - Better (normalized) source:
    - alerts_all.alert_node_id -> edge_nodes.id -> edge_nodes.node_code

3) Forensic View header
- Alert ID / Source / Time: same as #2

4) Forensic “Recent Flow Sequence (10 Steps)” table (FORENSIC_FLOWS mock)
Two ways to store/retrieve:
- A) Stored on alert as JSON (current DBML)
  - alerts_all.alert_sequence_steps_json: array of 10 objects with:
    - step_ts, step_src_ip, step_dst_ip, step_protocol, step_length, step_tcp_flags
- B) Stored as flows and related to alert (not modeled as table; would require a link table if you want strict relational)

If you use JSON approach, map:
- Time     -> step_ts (or preformatted string)
- Src IP   -> step_src_ip
- Dst IP   -> step_dst_ip
- Proto    -> step_protocol
- Len      -> step_length
- Flag     -> step_tcp_flags

5) Attack Type Distribution (ATTACK_DIST mock)
- Use: alerts_all
  - Group by: alerts_all.alert_threat_type
  - Count: alerts_all.alert_id

6) Edge Node Fleet mini list (NODES mock: cpu/ram/temp)
- Use: edge_nodes snapshot columns (fast listing)
  - cpu -> edge_nodes.current_cpu_percent
  - ram -> edge_nodes.current_ram_percent
  - temp -> edge_nodes.current_temperature_c
- Or from node_telemetry (normalized time-series)
  - node_telemetry.cpu_percent / ram_percent / temperature_c WHERE ts is latest per node_id

7) AI Performance Panel / F1 history (F1_HISTORY mock)
- Use: model_versions.f1_score over time
  - model_versions.created_at for x-axis
  - model_versions.f1_score for y
  - filter: model_versions.status = 'deployed' (or model kind)

UI: realtime stream of flows + alert stack + edge-to-cloud sync status

1) Dual-Stream Raw Data Table (flows state; Flow interface)
- Use: network_flows_feedback_all (as the base flow log)
  - timestamp -> network_flows_feedback_all.flow_ts
  - protocol  -> network_flows_feedback_all.flow_protocol
  - srcPort   -> network_flows_feedback_all.flow_src_port
  - dstPort   -> network_flows_feedback_all.flow_dst_port
  - duration  -> network_flows_feedback_all.flow_duration_s
  - bytes     -> network_flows_feedback_all.flow_total_bytes
  - isAnomaly -> network_flows_feedback_all.is_anomaly

2) Active Sequence Radar (radarData mock)
- Derived metric over time; suggested source:
  - network_flows_feedback_all.anomaly_score (sliding window)

3) Live Alert Stack (Alert interface: severity/status/verdict/sequence[])
- Use: alerts_all
  - id         -> alerts_all.alert_id
  - time       -> alerts_all.alert_first_seen_at
  - threat     -> alerts_all.alert_threat_type
  - severity   -> alerts_all.alert_severity ('critical'/'warning')
  - status     -> alerts_all.alert_status ('pending','verifying','confirmed','false-positive')
  - verdict    -> alerts_all.alert_verdict_text
  - sequence[] -> alerts_all.alert_sequence_values_json (array[10] numbers)

4) Edge-to-Cloud Sync widget (CPU/Temp/Latency)
- From node/telemetry:
  - node_telemetry.cpu_percent / temperature_c / latency_ms (latest)
  - optionally cached into edge_nodes.current_* columns

src/modules/reports/view/components/ReportingAuditLogs.tsx
============================================================
UI: audit log table with timestamp/user/action/target/status

Since DBML avoids creating a dedicated audit table, suggested storage:
- Use audit fields attached to domain tables and UNION them in reporting queries:
  - alerts_all.audit_* (for alert actions)
  - retrain_jobs_all.audit_* (for retrain actions)
  - deployments_all.audit_* (for deployment actions)

Fields:
- timestamp -> *_audit_created_at
- user      -> *_audit_user_display_name (or *_audit_user_email)
- action    -> *_audit_action
- target    -> *_audit_target
- status    -> *_audit_status
